# 仓颉猜数字游戏（Cangjie Guess Number）

一个用[仓颉语言（Cangjie）](https://cangjie-lang.cn/)编写的命令行猜数字小游戏，体现**趣味性、启发性与示范性**：
程序随机生成一个 1~100 的整数，玩家反复猜测；程序给出“偏大/偏小”的方向提示与“很热/很冷”的距离提示，
猜中后依据猜测次数给出评级。

> 已通过 **Cangjie 1.0.0.5 (cjnative, x86_64-w64-mingw32)** 编译运行验证。

## 核心理论与技巧

### 1. 伪随机数：从种子到区间

计算机产生的是**伪随机数**：给定初始“种子（seed）”，通过确定性算法得到看似无序的数列。
同种子的序列完全确定，因此：

- 不指定种子时，`Random()` 通常以时间/系统熵自动播种，保证每次运行结果不同；
- 固定种子可用于**复现 bug**，便于调试；
- `nextInt64(range)` 直接返回 `[0, range)` 的均匀整数，是最安全的“落区间”方式。

```cangjie
func randInt(min: Int64, max: Int64): Int64 {
    let r = Random()
    let range = max - min + 1      // 闭区间要 +1，经典 off-by-one 陷阱
    return min + r.nextInt64(range) // ∈ [0, range) + min ⇒ [min, max]
}
```

> **技巧**：不要写 `nextBits(64) % range` 再手动取绝对值。
> 标准库 `nextInt64(range)` 已处理符号与偏置，更短、更对、更安全。

### 2. 绝对值与分段函数

“猜得有多近”在数学上是绝对值 `|guess - target|`。程序用 `if` 手动展开：

```cangjie
let diff = if (guess > target) { guess - target } else { target - guess }
```

把“距离”映射成“温度文字”，是**查表式映射**：用递进的 `if/else if` 实现“多档位量化”。

⚠️ 判断顺序**必须从小到大**：若先写 `diff <= 30`，则 `5` 会被误判为“有点冷”。

### 3. 防御式编程

程序假设用户“什么都可能输入”：空行、字母、越界数字。每一层都做校验：

| 风险 | 防御 | 结果 |
| --- | --- | --- |
| 直接回车 | `if (input == "")` | 提示并重试（`continue`） |
| 非数字 | `Int64.parse` 解析语义 | 由语言层处理（可加 `try`） |
| 越界 | `if (guess < 1 || guess > 100)` | 拒绝并继续循环 |

> 所有“与人交互”的程序，都必须把输入当作**不可信数据**来校验。
> 这是从“玩具代码”走向“工程代码”的分水岭。

### 4. 信息论视角：反馈的信息量

- “偏大/偏小”把搜索空间砍掉一半（**二分查找**，每次约 1 bit 信息）；
- “很热/很冷”提供**梯度方向**，帮助人类做“插值”而非“二分”。

程序“显得智能”的原因：**它不是更聪明，而是给了更丰富的反馈。**

理论上，1~100 用完美二分只需 `⌈log₂100⌉ = 7` 次。
因此评级阈值“≤7 次 = 大师级”**有信息论依据**，不是拍脑袋：

```cangjie
if (count <= 4)  { "传说级 · 二进制先知" }
else if (count <= 7)  { "大师级 · 二分查找选手？" }  // log₂100 ≈ 6.64
else if (count <= 12) { "正常人类" }
else                { "随机森林（字面意思）" }
```

### 5. 强类型：把错误挡在编译期

仓颉是**静态强类型**语言：`Int`、`Int64`、`UInt64` 之间**不允许隐式转换**。

- ✅ 好处：`100` 与 `100u64` 不会偷偷混用，溢出/符号错误在编译期暴露；
- ⚠️ 代价：必须显式写 `Int64(x)`、`Int(x)`，且跨位宽构造（如 `Int(Int64)`）未必有重载。

**最佳策略**：在一个模块内**统一使用一种整数类型**（本例全用 `Int64`），从源头消灭类型转换。

## 关键 API 速查

| API | 所属 | 说明 |
| --- | --- | --- |
| `Random()` | `std.random` | 构造伪随机数生成器（自动播种） |
| `r.nextInt64(n)` | `std.random` | 返回 `[0, n)` 的 Int64，最安全的落区间方式 |
| `Int64.parse(s)` | `std.convert` | 字符串 → Int64（扩展函数，需导入 convert） |
| `getStdIn().readln().getOrThrow()` | `std.env` | 从标准输入读取一行 |
| `println` / `print` | 标准库 | 输出（println 换行） |
| `"${x}"` | 语言特性 | 字符串插值 |
| `if / else` | 语言特性 | 分支**必须**用 `{}` 包裹（即使单行） |

## 避坑指南

| ❌ 错误写法 | 原因 | ✅ 正确写法 |
| --- | --- | --- |
| `r.nextBits(64).toInt()` | 仓颉无 `.toInt()` 成员方法 | `r.nextInt64(range)` |
| `(...).abs()` | `abs` 不是 Int64 成员方法 | 用 `nextInt64` 直接得正数，或 `std.math.abs` |
| `Int(v % Int64(range))` | 跨位宽构造 `Int(Int64)` 未必有重载 | 全程 `Int64`，不混用类型 |
| `if (x>0) return 1 else return 0` | 仓颉要求分支必须 `{}` | `if (x>0) { 1 } else { 0 }` |
| `readLine()` | 裸函数未声明 | `getStdIn().readln().getOrThrow()`（需 `import std.env.*`） |
| `import std.io.*`（未使用） | 冗余导入，编译器警告 | 只导入真正用到的包 |

> **心法**：遇到 `no matching function for operator '()'`，几乎总是
> “函数/构造器不存在或类型不匹配”——先查类型，再查 API 是否真存在，不要盲目加 `.toXxx()`。

## 扩展与思考

1. **反向模式**：让玩家想数字，程序用**二分查找**来猜，演示“机器如何用信息论赢你”。
2. **难度自适应**：根据历史 `minDiff` 动态调整数字范围，形成“难度曲线”。
3. **持久化**：用文件记录“最少次数”排行榜，引入 `std.fs`。
4. **面向对象**：把 `target / count / minDiff` 封装进 `class Game`，体会建模。
5. **异常安全**：用 `try/catch` 包裹 `Int64.parse`，优雅处理“输入 abc”。
6. **可测试性**：把 `Random` 通过参数传入并固定种子，让游戏逻辑可单元测试。

> **一句话总结**：60 行代码，讲完了“变量是记忆、循环是重复、函数是抽象、类型是契约、反馈是智能”。
> 编程的真正趣味，不在于让机器听话，而在于**把模糊的直觉，翻译成严丝合缝的逻辑**。

## 代码规范

本示例遵循以下规范（便于阅读与教学）：

- **代码行数**：有效代码 &gt; 50 行，避免冗余；
- **缩进**：统一 4 个空格；
- **大括号**：类型定义与控制流（`if / else / while / func`）的**左大括号与前文保持在同一行**，不独占一行；
- **留白**：左括号前、右括号后、逗号后用一个空格与其他内容分隔，如 `if (diff == 0)`、`randInt(1, 100)`。

```cangjie
// ✅ 规范示例
if (count <= 7) { println("大师级") }

// ❌ 不规范
if(count<=7){
    println("大师级")
}
```
