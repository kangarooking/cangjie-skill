# 视频蒸馏的证据检查

在阶段 0 处理带课件、代码、演示或图表的视频，或用户明确要求核对画面时读取。它补充文本理解，不改变仓颉的阶段顺序，也不把普通摘要自动扩成安装 Skill 或修改项目的任务。

## 按结论选择材料

1. 确认原视频、标题和版本，记录字幕是否为自动转写。利用字幕定位影响方法、边界或效果判断的时间段。
2. 实际查看这些时间段的画面或可核对的原课件。操作演示应覆盖必要的输入、动作和结果；一张结束截图不能证明此前操作或持续运行。静态讲述不要求固定数量的截图，也不要求逐秒观看。
3. 对保留的关键主张记录：时间点、证据位置、看到的内容、支持的有限结论、尚未验证的部分。可以直接写入 `BOOK_OVERVIEW.md`，无需另造一套清单。
4. 将证据索引与材料限制传给提取器。候选依赖具体画面时，提取器须查看该证据；不能只复述上游摘要就声称独立核验。

## 不混用证据强度

- 字幕能支持讲者说了什么，不能自动证明屏幕展示了什么或操作成功。
- 画面上的百分比、模型评分、架构图和界面提示仍需解释其口径。缺少题集、样本量或计算方式时，记录为课件主张，不当成可复现提升或项目效果承诺。
- 分开记录现场演示、教学假设、讲者案例自述和自己的应用建议。评分结果与评分标准也要区分：分数可见，不代表评分标准必然合理。
- 同一演示中的输入、输出和重复讲解不算多个独立案例。阶段 1.5 仍按原规则判断独立佐证。
- 阅读全字幕并抽看若干关键时间点，就如实描述该范围；不写成完整观看了全部视频。

## 画面不可获取时

先使用现有可访问的视频、原课件或用户提供的截图。不能获取时，明确列出受影响的主张，只蒸馏文本能支持的部分；将依赖视觉证据的候选暂缓。若用户明确要求视觉核验，说明该部分仍未完成并指出缺少的材料，不要用通用知识补造画面内容。

用户只给文字稿并要求文字分析时，尊重这个边界；不要求无关视频材料。用户点名仓颉但只要求阶段 0 总结时可以完成该阶段，不要未经要求生成并安装整套 Skills。用户要求完整蒸馏并应用时，保留原流程的确认、构造、测试和安装状态，不能把阶段 0 总结或候选清单叫作已交付的 Skill。

## 历史回放

一次 RAG 课程分析中，检索找到依据，但答案仍加入来源未支持的步骤；另一张效果提升图缺少足够的题集和统计口径。改进后的做法是在提取前核对相关输入、答案、评语和图表，让这些观察进入候选的边界说明。时间点和截图数量只服务于该材料，不是其他视频必须照抄的配额。
